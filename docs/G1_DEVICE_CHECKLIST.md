# 真机核查清单（G1 完成标志的后半）

**当前状态：`NOT_MET` —— 未连接设备，本清单尚未执行。**
本文件把"要做什么、看什么、记什么"固定下来，避免临场凭记忆操作。
脚本 `tools/device_verify.ps1` 默认**只读**，写入必须显式加开关。

---

## 0. 为什么这一步不能省

G1 的完成标志是两句：前半（"虚构时间线能在同一集不同位置改变决定"）已由
`PipelineEndToEndTest` 覆盖并通过；后半（"真实条目显示前受控"）**只能**在真机上成立。

本项目已多次出现"代码写了 / 测试过了 / 构建成功了，但实际没接线"，
因此**不接受**"编译通过"当作这一项的证据。

## 1. 只读核查（不需要安装任何东西）

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\device_verify.ps1
```

这一条会读出（不写入任何东西）：

| 项目 | 用途 |
|---|---|
| 品牌/型号/设备代号/Android 版本/SDK/ABI | 核对之前记录的设备信息是否仍成立 |
| `su` 可执行文件与 Magisk 包 | **只读**判断是否有 root；不会尝试提权 |
| 官方 Animeko 的 `versionCode` / `versionName` | **解除假设 A1**：只有 50406 才能说"版本与锁定的上游提交一致" |
| 官方 Animeko 的 APK SHA-256 | 从设备读回副本后计算，不依赖任何官方发布信息 |
| 自编译版是否已安装 | 判断是首次安装还是升级 |

**判定规则（必须如实记录）：**

- 官方 Animeko `versionCode` **不是** 50406 → 假设 A1 **不成立**，
  必须在 `STATE.json` 里改掉，并重新评估 `docs/INTEGRATION.md` 里的接入点证据
  （行号与符号是相对锁定提交而言的）。
- 官方 Animeko 未安装 → A1 无法验证，记为 `UNKNOWN`，不要写成"已核对"。

## 2. 安装自编译版（与官方共存）

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\device_verify.ps1 -Install
```

安全性由两道机制共同保证，**不是靠操作者小心**：

1. 包名是 `me.him188.ani.localguard`，与官方 `me.him188.ani` 不同 ⇒ 不可能覆盖官方 App；
2. 签名是本地 debug 密钥（SHA-256 `966fba3c…51c0`），与官方发布密钥不同
   ⇒ 系统也**不会允许**它覆盖签名不同的官方包。

安装不会删除任何用户数据。若要回退，直接卸载本包即可；**不要**为了让安装通过而去卸载官方 App。

> 若报 `INSTALL_FAILED_UPDATE_INCOMPATIBLE`，说明设备上已存在同包名但签名不同的版本——
> 这属于预期之外的情况，应先报告，不要自行卸载任何东西。

## 3. 手动核查项（G1 的实际判定内容）

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\device_verify.ps1 -Install -Launch
```

启动后进入：**播放页 → 弹幕设置 → 「本地弹幕过滤（非官方）」**，逐项确认：

| # | 检查项 | 期望 | 不通过意味着什么 |
|---|---|---|---|
| 1 | 总开关初始状态 | **关闭** | 默认开启会改变官方 Animeko 的既有行为 |
| 2 | 状态行文案 | 显示"原型阶段…尚未内置 AI 模型"一类说明 | 若显示成"已启用/已防护"，是**虚假陈述**，属严重问题 |
| 3 | 打开开关后弹幕表现 | 弹幕**照常显示**（APK 内没有剧情包，不该拦任何东西） | 若开始大量消失，说明有误拦 |
| 4 | 三档切换 | 状态行更新，播放行为无异常、不卡顿、不崩溃 | |
| 5 | 杀掉进程重进 | 开关与档位**保持** | 说明持久化没生效 |
| 6 | 展开"显示详细计数" | 逐条统计可展开，且 `evaluated` 有数值 | 若 `evaluated` 恒为 0，说明判定路径根本没被走到 |
| 7 | 播放中切换剧集 | 不崩溃；计数按集重置 | 会话隔离失效 |

**第 6 项是本次真机核查里最有信息量的一项**：它能在没有剧情包、没有模型的情况下，
独立证明"弹幕确实经过了判定路径"。若它恒为 0，那么后面所有"已接入"的说法都不成立。

## 5. 这一步**不能**证明什么

即使 7 项全通过，也**仍然不能**说"剧透防护已生效"。原因是客观的：

- `app/android/src/main/assets/story/` 里**没有任何剧情包**；
- `semanticsProvider` 仍返回 null（未安装任何模型）。

所以真机核查通过后，G1 的状态应写成
**"开关/状态/持久化/判定路径已真机验证；拦截效果未验证（无剧情包、无语义来源）"**，
而不是笼统的"G1 完成"。

拦截效果要成立，必须先有 G2（真实作品的剧情包）。
